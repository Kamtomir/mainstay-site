# mainstay-site

The source of Kamil Dashdamirov's site: the service "a quality system for AI-assisted development",
the free [mainstay](https://github.com/Kamtomir/mainstay) plugin, the case and the blog.
A static site: plain HTML, two languages, no server, no trackers, no forms. The instructions
below are in Russian.

---

Сайт услуги «система качества для разработки с ИИ-агентами»: главная, страница плагина,
страница кейса и блог, на английском (основной, адрес `/`) и русском (`/ru/`).

Сделан на [Astro](https://astro.build): он собирает обычные HTML-файлы из текстовых файлов, без
JavaScript на странице. Поисковики и ИИ-поисковики видят весь текст сразу.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Открывает сайт на `http://localhost:4321` и обновляет страницу при каждой правке.

```bash
npm run build
```

Собирает сайт в папку `dist/` и проверяет результат (`scripts/check.mjs`). Если проверка красная,
выкладывать нельзя: в каждой строке написано, какой файл и что исправить.

```bash
npm run preview
```

Показывает собранный сайт из `dist/` — ровно то, что попадёт на хостинг.

```bash
npm run typecheck
```

Проверяет типы в коде страниц. Нужна после правок в `src/`, для правок текстов не обязательна.

| Цифры кейса и команды, которыми они воспроизводятся | `src/data/case.ts` |

## Как поменять адрес, контакт и цену

Всё в одном файле, `site.config.mjs`:

- `url` — адрес сайта, сейчас `https://dashdamirov.dev`. Адрес, который заканчивается на
  `.example`, считается заглушкой: с ним сборка на GitHub падает намеренно, чтобы сайт с
  ненастоящим адресом нельзя было выложить.
- `consultUrl` и `consultHandle` — куда ведёт кнопка «Консультация» и что написано рядом.
- `product` — название и адрес продукта, о котором рассказано в блоке «Обо мне» (Catch Club,
  `https://catchclub.app`). Оттуда берётся кнопка под текстом; в самих текстах адрес пишется
  подстановкой `{productUrl}`.
- `price.amount` — цена в долларах. `price.show: false` заменяет цену фразой «после разбора».
  `price.intro` — необязательная строка «первым клиентам дешевле», например
  `{ amount: 1500, clients: 3 }`.
- `factsCheckedAt` — дата, когда факты на сайте последний раз сверялись с `CASE.md`. Двигать
  только после настоящей сверки.
- `publishedAt` — день первой публикации, 23 ноября 2026 года. Больше не менять.

## Как добавить статью

Одна статья — один файл. Создайте `src/locales/ru/blog/moya-statya.md`:

```markdown
---
title: "Заголовок до 60 знаков"
description: >-
  Одно-два предложения до 200 знаков: о чём статья и что в ней измерено.
date: 2026-12-01
updated: 2026-12-01
sources:
  - label: "mainstay, CASE.md"
    href: https://github.com/Kamtomir/mainstay/blob/main/CASE.md
---

Текст статьи в Markdown.
```

- Имя файла становится адресом: `/ru/blog/moya-statya/`. Пишите его латиницей через дефис.
- Перевод — файл **с тем же именем** в папке другого языка (`src/locales/en/blog/moya-statya.md`).
  Тогда страницы сами сошлются друг на друга. Статья на одном языке тоже допустима: сборка
  только предупредит.
- `date` — день публикации, `updated` — день последней заметной правки. Обе даты видны на
  странице и в разметке для поиска.
- `sources` обязательны: у каждой статьи названы источники.
- `draft: true` прячет статью с сайта.
- Ссылки на свои страницы пишутся с языком: `/ru/plugin/` в русской статье, `/plugin/` в английской.
- Статья попадает в список блога, RSS, sitemap, `llms.txt` и `llms-full.txt` сама.

## Как добавить язык

Один язык — одна папка.

1. Скопируйте `src/locales/en` в `src/locales/<код>`, например `src/locales/de`.
2. Переведите файлы в новой папке. В `ui.yaml` в блоке `lang` поставьте название языка, короткую
   подпись для переключателя и коды (`htmlLang: de`, `ogLocale: de_DE`, `dateLocale: de-DE`,
   `numberLocale: de-DE`).
3. Соберите сайт: `npm run build`. Адреса `/de/...`, переключатель языка, hreflang, sitemap, RSS и
   `llms.txt` появятся сами. Если в переводе пропущено поле, сборка скажет какое.
4. Нарисуйте картинку-превью для нового языка: `npm run og`, затем ещё раз `npm run build`.

Основной язык (тот, что живёт на `/`) задаётся в `site.config.mjs`, поле `defaultLang`.

## Цифры и подстановки

Каждая цифра кейса записана один раз, в `src/data/case.ts`, и взята из `CASE.md` и `README.md`
репозитория mainstay. В текстах вместо цифр стоят подстановки в фигурных скобках, например
`{unitTests}` или `{mergedPrs}`: страницы, блок «Коротко», разметка для поиска и `llms.txt` берут
одно и то же число. Опечатка в имени подстановки роняет сборку.

Когда `CASE.md` меняется:

1. поправьте `src/data/case.ts`;
2. найдите старое число в статьях (`src/locales/*/blog/`): статьи — обычный текст, цифры в них
   вписаны руками;
3. в русских текстах проверьте окончания слов рядом с числами («тестов», «набора», «случая»);
4. поставьте новую дату в `factsCheckedAt`.

Внутри строк YAML работает простая разметка: `` `код` ``, `**жирный**`, `[текст](/путь/)` или
`[текст](https://...)`. Путь, который начинается с `/`, сам получает приставку языка.

## Как устроен вид

Сайт светлый, с тёмными полосами. Автоматической тёмной темы нет: страница сама чередует светлое
и тёмное.

- **Полосы.** Страница сложена из полос во всю ширину (`Band.astro`): белая, светло-серая, тёмная
  ночная и зелёная в конце. Две соседние полосы не бывают одного цвета.
- **Цвет что-то значит**, как в запуске проверок: зелёный — «прошло», красный — «упало». Для
  украшения эти цвета не используются.
- **У каждого блока главной свой приём**, чтобы читатель запоминал, где что: история по шагам и
  запуск проверок на первом экране, три плитки «дорогих мест», списки «плюс и минус», листы-файлы,
  линия шагов, крупные цифры с историей запусков точками, чек с ценой, раскрывающиеся вопросы,
  карточка автора. Новый блок получает свой приём, а не ещё одну сетку одинаковых карточек.
- **Шрифты.** Заголовки — узкий Sofia Sans Extra Condensed, текст — Sofia Sans, код — Martian Mono.
  Моноширинный шрифт только там, где на странице правда код, имя файла или вывод программы.
- **Движение** сделано на CSS и только там, где оно что-то показывает: запуск проверок
  проигрывается при открытии, линия шагов и точки запусков дорисовываются при прокрутке, сверху
  идёт полоска «сколько прочитано». Если человек просил меньше движения, всё стоит на месте.
- **Кнопка под запуском проверок** («Исправить и запустить снова») — это галочка и CSS, без
  скриптов: красный запуск становится зелёным и обратно.

Тексты для этих блоков лежат в `home.yaml`; у каждого поля там есть пояснение.

## Что проверяет сборка

`npm run build` заканчивается проверкой `scripts/check.mjs`. Она читает собранные страницы и
падает, если:

- заголовок страницы длиннее 60 знаков или описание длиннее 200;
- на странице не один заголовок первого уровня;
- нет canonical, hreflang или пара hreflang не ссылается обратно;
- разметка JSON-LD не разбирается;
- страница подключает файл со скриптом (текст должен читаться без JavaScript);
- внутренняя ссылка ведёт на страницу, которой нет;
- в текст попала незаполненная подстановка;
- страницы нет на одном из языков (для статьи — только предупреждение);
- нет `sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt` или `rss.xml`;
- нет картинки-превью;
- в исходниках есть невидимые символы.

Проверка не открывает страницы в браузере и не оценивает внешний вид.

## Картинки-превью

Telegram, Slack и LinkedIn показывают картинку, когда кто-то отправляет ссылку на сайт. Картинки
лежат в `public/og-<язык>.png` и рисуются скриптом из имени и главного заголовка:

```bash
npm run build && npm run og && npm run build
```

Скрипту нужен Google Chrome на компьютере. Запускать его нужно только после смены имени или
главного заголовка; обычной сборке Chrome не нужен.

## Выкладка

Сайт живёт на GitHub Pages по адресу `https://dashdamirov.dev`. Репозиторий открытый:
`Kamtomir/mainstay-site`.

Каждое обновление ветки `main` на GitHub собирает сайт, прогоняет проверки и выкладывает `dist/`.
Красная проверка ничего не выкладывает. Настройка лежит в `.github/workflows/deploy.yml`.

Посмотреть последние выкладки:

```bash
gh run list --repo Kamtomir/mainstay-site --limit 5
```

Что настроено вне репозитория:

- GitHub, Settings → Pages: Source — «GitHub Actions», Custom domain — `dashdamirov.dev`, включено
  Enforce HTTPS.
- DNS домена лежит в Vercel, там же домен куплен: четыре записи A и четыре AAAA на адреса GitHub
  Pages и запись CNAME `www` → `kamtomir.github.io`. Сами адреса — в документации GitHub Pages.

Открытый репозиторий виден всем вместе с историей коммитов. В коммитах и файлах пишите только то,
что можно показать.

Подробная история до первой публикации осталась на этом компьютере, в ветке
`local-history-2026-11-23`. В GitHub её не отправлять.

## Что сделано для поиска и ИИ-поиска

- Весь текст есть в HTML при загрузке, без клиентской отрисовки.
- Блок «Коротко» на главной и на странице кейса: самодостаточные факты с датой проверки.
- Разметка JSON-LD: человек, сайт, услуга с ценой, вопросы и ответы, статья, набор цифр кейса,
  исходный код mainstay, «хлебные крошки».
- `llms.txt` и `llms-full.txt` на каждом языке, собранные из тех же данных, что и страницы.
- `sitemap.xml` с переводами и датами, `robots.txt`, RSS на каждом языке.
- canonical и hreflang между языками, `x-default` на основной язык.
- У статей видны дата публикации и дата обновления.

## Правила для текстов

- Тексты пишутся голосом автора: короткие фразы, одна мысль — одно предложение, свои истории вместо
  общих слов. Термин объясняется простыми словами там, где встречается впервые. Блок «Коротко»
  написан для поисковиков и стоит внизу страницы.
- Цифры — только из `CASE.md` и `README.md` репозитория mainstay.
- Без обещаний результата и гарантий: пишем, что делается и что было измерено.
- Места работы, должности и контакты — только те, что подтвердил автор.
- Прямо сказано, кто что делает: код клиента читает ИИ-агент под руководством автора, автор
  проверяет каждую находку. Ответы про доступ, провайдера ИИ и NDA не убирать.
- Сайт обещает, что код клиента обрабатывается под коммерческим аккаунтом ИИ (ключ API), где он не
  идёт в обучение моделей. Личная подписка для кода клиента не используется. Если порядок работы
  меняется, эту фразу нужно менять в тот же день.
- Форм и трекеров на сайте нет.
